Store provider API keys in the CLT registry so Models-page keys take priority over environment variables (FEATURE, AGENT, TUI)

COMPLETED 2026-09-18: The Models page now stores a provider key in `model_providers.api_key` (migration 18) with `k`, entered through a hidden input that masks the value and never renders it again. The `KEY` column and `Auth` detail line report only the source (`clt`, `env`, `env-missing`, `none`). Resolution order is the CLT-stored key, then the provider's `env_key`, then Codex's own configured login; only the selected provider's variable is injected into the Codex child, for both automated runs and interactive handoff. Model discovery authenticates the same way, and a custom endpoint with no `env_key` gains `OPENAI_API_KEY` so a stored key actually reaches it. The agent state directory is forced to `0700` because the registry, WAL, and recovery snapshot can now hold secrets, and `AgentModelProvider` redacts the key in `Debug`. Reads and writes keep the pre-key column set while migration 18 is deferred behind pinned workers. Checks: `cargo fmt` on touched files; `cargo clippy --no-deps --locked --all-targets --all-features -- -D warnings`; `cargo test --locked --all-targets --all-features` (581 unit + 4 architecture + 14 CLI passed).
